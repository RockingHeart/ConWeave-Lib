# 此为开发规范

- (1) 宏的禁用
    - 尽量避免使用宏

- (2) 模板形参命名
    - 若是非耦合的模板变量，或者概念
        - 标准小蛇型
    - 其它情况：标准大驼峰或根据情况而定

- (3) 函数名及形参-变量-类类型-类型别名-概念 命名
    - 标准小蛇形

- (4) 若函数参数的数目大于等于3个时，或数目大于等于2个，与函数参数占用参数列表的空间较长时
    - 若函数体的复合语句数目大于3个时
        - 参数列表起始符号（'('）与函数名尾部隔离，隔离符号为空格，通常隔离一个，并与参数列表的第一个参数紧凑一起不换行
        - 对齐均使用空格或tab
            - 使参数类型对齐（不对齐类型属性）
            - 使参数命名对齐
        - 最后一个参数依照对齐准则，但参数列表的最后一个参数与参数列表结尾符号（')'）紧凑一起

- (5) 函数头部属性
    - 头部属性位于函数声明之上

- (6) 函数尾部属性
    - 若函数参数的数目大于等于3个时
        - 尾部属性位于参数列表之下
    - 若函数参数的数目小于3个时
        - 尾部属性与函数声明并行

- (7) if consteval 块
    - 入口标识需换行

- (8) namespace
    - 入口标识需换行

- (9) 项目最小子单元
    - 以模块编写的最小 子单元 至少包含有一个导出模块
        - 导出模块需细分 子单元 的组成部分

- (10) switch
    - 入口标识需换行
    - 每个case礼毕后需要换行
        - 若case较多，建议每个case下封装成函数

- (11) goto
    - 若goto下的代码是为一个可封装的步骤，则建议封装成函数
